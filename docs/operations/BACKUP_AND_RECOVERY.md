# 数据备份与恢复

纯净领域的作品原图不会塞进数据库：SQLite 保存索引、作品/作者元数据、分类、偏好、审查缓存和显式整理任务；托管下载仍位于用户选择的图片目录。因此完整恢复需要分别考虑数据库与图片文件。

## 建议备份

1. 在“设置 → 画廊与存储”点击“备份数据库”。应用通过 SQLite `VACUUM INTO` 创建一致的单文件快照，不需要退出程序。
2. 另行备份 Pixiv 保存目录。自定义目录显示在同一设置卡；默认是系统图片目录下的 `Digital Sanctuary/Pixiv`。
3. 若要保留 Pixiv 登录 session，应在应用完全退出后备份用户数据目录。开发版/早期版本通常为 `%APPDATA%\digital-sanctuary`；安装版以 Electron 实际用户数据目录为准。

数据库当前 schema 版本为 `2`。从旧 `artworks` 页面模型首次迁移到作品模型前，程序还会在原数据库旁创建一次 `library.db.pre-v2.bak`。

## 恢复数据库

1. 完全退出纯净领域，并在任务管理器确认 `DigitalSanctuary.exe`、`electron.exe` 和 `sanctuary-vision.exe` 均已结束。
2. 找到当前用户数据目录中的 `library.db`。不要在应用运行时替换它。
3. 先把现有 `library.db`、`library.db-wal` 和 `library.db-shm` 复制到另一个安全目录；不要直接永久删除。
4. 将备份文件复制为 `library.db`，并移走旧的 `library.db-wal`/`library.db-shm`，避免把不匹配的 WAL 套到恢复文件上。
5. 启动应用，检查作品数、分类、作者和设置。程序会幂等补齐缺失的新表与 schema 记录。

如果恢复后的作品卡显示文件缺失，说明数据库索引指向的图片目录没有一并恢复。先把图片放回原路径；当前版本不会擅自猜测或批量改写外部文件路径。

## 版本边界

- 版本 `2` 新增自定义偏好、显式模型任务和独立分析结果；它不会覆盖主动下载的可信状态。
- 新版本读取旧数据库前会运行幂等迁移。旧版本不保证能读取由新版本写入的数据库；降级前请恢复对应版本的备份。
- 卸载程序不应被当作备份工具。安装包验收会在隔离目录测试安装与卸载，但用户数据仍应由用户主动备份。
