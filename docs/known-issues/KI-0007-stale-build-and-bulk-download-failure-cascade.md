# KI-0007：旧构建掩盖更新与收藏下载失败级联

- 状态：已修复 / 待真实收藏任务复核
- 发现日期：2026-08-12
- 优先级：P0

## 现象

- 源码与 Git 已有多次更新，但启动后的界面完全没有变化。
- 收藏任务最终显示“下载完成”，同时出现“作品 34/575、541 个失败、页面 53/53”。

## 根因

1. `启动纯净领域.cmd` 只启动 `apps/desktop/out`，从不执行构建。源码最后修改时间为 2026-08-12 04:40，而运行产物仍停留在 2026-08-11 20:55。
2. 完成阶段无条件写成 `complete`；作品分子只统计成功项，失败项没有计入“已处理”，页面总数又只来自成功进入下载流程的作品。
3. 每个作品错误只写控制台并继续，遇到全局网络/限流故障时会把后续几百个作品全部记成独立失败。
4. 403 被当作频率限制做五次指数退避，单个作品累计等待可超过 15 分钟，但 403 也常表示作品下架或无权访问。

## 修复

- 启动器先确认旧窗口已关闭，再执行生产构建；构建失败时不启动旧产物。
- 增加 `partial` 阶段；进度改为“已处理 / 成功 / 失败 / 已知页面”。
- 429、网络异常和 5xx 只做两次有界重试，仍失败就停止批次；连续 5 个普通作品失败同样熔断。
- 401 立即提示会话失效；403 作为单作品不可访问处理，不进行分钟级盲等。
- 重新运行收藏任务时，已完整索引且文件存在的作品走快速跳过，因此可以继续处理未完成部分。
