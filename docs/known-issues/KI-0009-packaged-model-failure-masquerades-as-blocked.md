# KI-0009：安装包模型故障被表现为全部图片遭到拦截

- 状态：代码已修复 / 旧安装包不含修复 / 待重新打包验收
- 记录日期：2026-08-23
- 优先级：P0

## 现象

安装版应用中视觉模型可能没有正确挂载或启动，但探索页把每一次审查失败都转换成 `allowed: false`，最终让大量图片显示成“已拦截”。这不是所有作品都命中了用户的元素规则。

## 根因

1. `VisionClient` 在子进程刚创建时就把 `available` 初始化为 `true`，没有等待模型加载。
2. Python 服务原先延迟到第一张图片才创建 ONNX session，没有启动就绪握手。
3. 探索错误分支把进程退出、模型缺失和请求超时统一返回为“不允许显示”。

## 已实施修复

- 协议增加 `health-check / health-check-result`；模型文件、标签表和 ONNX session 完成装载后才报告 ready。
- 应用启动阶段执行一张内置小图的真实推理，自检通过后才开放受保护探索。
- 探索结果增加 `unavailable`，与真实 `blocked` 完全分离。
- 模型未就绪时隐藏 Pixiv WebContentsView，只显示一个总故障页，提供重试和明确的“本次无保护浏览”。
- 安装包 smoke test 现在同时验证就绪握手和真实推理。

## 验收要求

重新生成安装包后至少覆盖：完整模型、缺少 `model.onnx`、缺少标签表、损坏模型和视觉进程闪退。后四种情况都只能显示一个模型故障页，不能生成逐图拦截遮罩。
