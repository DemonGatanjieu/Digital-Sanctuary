# KI-0003：探索页普通作品误拦，第一方广告漏拦

- 状态：已确认 / 暂停修复，等待下一轮复现
- 发现日期：2026-08-11
- 优先级：P0
- 相关提交：`158aa52`、`3731bb8`、`9a1962d`

## 现象

用户反馈探索页同时存在两类错误：

1. 大量正常作品被内容审查误拦，当前过滤结果不具备可接受的浏览准确率。
2. Pixiv 第一方推广仍然可见，包括：
   - 页面上方带 `PR` 标记的推广卡片；
   - `Hitenkei's Booth` 商品/合作推广卡片。

用户提供的截图已作为本次回归证据：普通作品误拦与 PR/BOOTH 广告漏拦同时出现。

## 影响

- 探索页的核心体验被破坏：正常作品被隐藏，广告仍然占据可见区域。
- 不能简单降低所有元素阈值来“修复”误拦，因为这可能放过真正的血腥、猎奇或断肢内容。
- 不能把 Pixiv 第一方图片域名整体加入网络黑名单；普通作品和广告共用 Pixiv 图片 CDN。

## 当前推测

- `img-master`、`img-original` 和 `custom-thumb` 请求目前无法仅凭 CDN URL 区分普通作品与第一方广告；页面级 DOM 识别可能发生在图片请求之后。
- 实际 Pixiv 广告 DOM 结构与脱敏 fixture 或当前适配器假设不一致，`PR` 标题可能和广告卡片处于兄弟节点、虚拟列表容器或动态 shadow/portal 结构中。
- 普通作品误拦需要结合占位层显示的命中标签、置信度、规则阈值和模型版本分析，暂不能归因于单一规则。

## 下一次修复前需要收集

- 一张被误拦普通作品的占位层截图，包含命中原因和置信度。
- 真实 Pixiv 页面中 PR/BOOTH 卡片的最小 DOM 结构、图片 URL、链接 URL 和插入时序。
- 同一页面的内容审查计数、第一方推广计数和网络广告计数。
- 确认运行的是最新构建，并且没有旧 Electron 进程占用单实例锁。

## 暂不采取的处理

- 不恢复年龄分级过滤。
- 不把所有 Pixiv/pximg 图片放行。
- 不把 `PR` 作为普通文本子串全局匹配。
- 不在没有命中原因证据时全局调低或关闭内容规则。
