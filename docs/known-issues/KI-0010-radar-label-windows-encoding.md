# KI-0010：Windows 下技术雷达轴标签乱码

- 状态：已修复 / 自动兼容旧缓存 / 待用户重启后目视验收
- 修复日期：2026-08-30

## 现象

“确定性技术特征”雷达的数值和多边形正常，但六个中文轴名显示为包含 `�` 的乱码。雷达标题、按钮和其他界面中文仍然正常。

## 根因

技术画像由 Python 视觉子进程计算。Windows 上子进程标准输出可能继承系统 GBK 代码页，而 Electron 主进程的 Node 流按 UTF-8 解码。`json.dumps(..., ensure_ascii=False)` 输出的中文因此在 JSONL 协议边界被错误解码；乱码随后又被保存进 SQLite 缓存。

这不是字体缺字或 SVG 排版问题。标题正常而轴名损坏，正是“静态 Renderer 文案正常、子进程动态数据损坏”的边界证据。

## 修复

1. Python 服务启动时把 stdin、stdout、stderr 显式设为 UTF-8；主进程同时设置 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`，覆盖开发 Python 和打包运行时。
2. 固定技术画像结果进入 UI 前通过套件定义校验，标签按维度 key 使用领域层权威中文名称，不再信任子进程传来的展示文案。
3. SQLite 保存和读取固定套件维度时同样规范化标签；已经写入的旧乱码不需要删除数据库或重新分析，重启新版应用后读取即恢复。
4. 新增真实 Python 子进程测试，覆盖中文文件名以及六个中文标签的 UTF-8 往返；数据库和 IPC 测试覆盖损坏标签自动恢复。

## 验收

1. 完全退出旧进程并重新启动最新构建；
2. 打开已有技术画像，六个轴应显示“色彩丰富度、明暗跨度、亮度均衡度、边缘密度、清晰度代理值、空间分布平衡”；
3. 不应要求删除旧画像或重新生成；新生成画像也必须正常；
4. AI 自选维度仍保留模型给出的动态名称，不能被固定套件标签覆盖。
