# KI-0004：视口驱动审查导致作品图全部停留在保护态

- 状态：已修复并重新启用 / 待真实 Pixiv 长滚动验收
- 发现日期：2026-08-11
- 优先级：P0（若重新启用）

## 现象

启用 document-start 图片保护、`IntersectionObserver` 候选上报和可见优先队列后，用户反馈 Pixiv 作品图几乎全部被隐藏，没有按预期在审查完成后恢复。

这不是“所有作品都命中了元素黑名单”。新管线会先取消缓存未命中的原始图片请求，再等待 preload 上报视口候选；因此只要“候选上报、主进程接收、审查完成、结果回传、图片重载”中的任一环节没有接上，页面就会表现为所有图片长期停留在保护态。

## 影响

- 探索页不可正常浏览，严重程度高于原有的滚动卡顿。
- 状态栏计数不足以确认断点位于 preload、IPC、队列还是图片重载。
- 继续在真实 Pixiv 动态页面上盲改容易再次产生大面积误伤。

## 已实施修复（2026-08-23）

- `ENABLE_VIEWPORT_REVIEW` 重新启用；未知图片由 document-start CSS 保持安静的等待态，进入或接近视口才排队。
- 结果拆为 `allowed / blocked / unavailable`；只有完整模型结果命中用户规则才能显示拦截遮罩。
- 模型故障由探索总状态页承接，WebContentsView 暂停显示，不再制造满屏“已拦截”。
- 新增明确的受保护/本次无保护模式切换，关闭保护时 preload 会清理等待态和遮罩。
- 新增画廊信任边界和模型故障门的自动回归测试。

## 待真实站验收

- preload 启动成功计数。
- 发现图片数、进入 400 px 视口范围数和 IPC 候选发送数。
- 主进程候选接收、队列入队/出队与结果回传计数。
- 放行后图片 `load/error` 事件、`currentSrc`、`naturalWidth` 和重试次数。
- 在真实 Pixiv 瀑布流中长滚动，确认等待态能够持续转为放行或真实拦截。
- 验证动态换图、不同尺寸 URL、多页作品以及网络短暂失败后的“重新检查”。
