# A5：10,000 作品 Electron 画廊基准

- 日期：2026-08-14
- 命令：`npm.cmd run benchmark:library`
- 环境：Windows、Electron 43.3.0、生产构建、独立临时 `userData`
- 数据：SQLite 中生成 10,000 个元数据作品，不读取真实账号和画廊文件

## 结果

| 指标 | 实测 | 门槛 |
| --- | ---: | ---: |
| 首批 60 张卡片可见 | 477 ms | 5,000 ms |
| 连续 36 次触底后已加载卡片 | 1,620 | 至少 120 |
| 滚动 P95 帧等待 | 73.7 ms | 80 ms |
| 最大帧等待 | 78.4 ms | 仅记录 |
| Renderer JS 堆 | 22 MB | 512 MB |
| 图片元素/解码 | 0 | 0 |
| 模型整理中心生产构建冒烟 | 可打开 | 可打开 |

基准通过 CDP 操作真实 Electron renderer，并使用页面实际的 `main` 滚动容器。首次运行曾因错误地滚动 `document` 而无法触发续载；修正基准后确认生产界面的观察器可以继续分页。

## 能证明什么

- 10,000 条数据库不会在首屏全量传给 React；首批保持 60 条。
- 连续分页时 UI 没有加载元数据 fixture 不存在的原图。
- 当前渐进分页和 `content-visibility` 在中等长度连续浏览中保持较低 JS 堆。

## 不能证明什么

- 元数据 fixture 不含真实缩略图，不能代替不同尺寸、编码和损坏图片的解码压力测试。
- 36 次触底没有把 10,000 张卡片全部留在 DOM 中；若以后支持“一次滚完整库”，应改为窗口化列表，而不是无限追加全部节点。
- 数值会随机器、显示缩放和 Electron 版本变化，门槛用于捕捉数量级回归，不作为硬件横向排名。
