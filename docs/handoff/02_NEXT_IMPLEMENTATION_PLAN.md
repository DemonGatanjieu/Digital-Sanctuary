# 交接二：下一步实施计划

本计划按优先级排序。每一阶段都应单独完成、测试和提交，不要把多个高风险改动揉进一次重写。

## P0：隐藏 Pixiv 第一方 PR 推广卡片

### 目标

隐藏页面中明确标记为“PR”或“推广”的整张卡片，同时不误伤普通作品、标题中偶然包含 `PR` 的作品或登录页面。

### 推荐步骤

1. 用隔离测试 session 和 CDP 检查真实 PR 卡片 DOM，记录：
   - “PR”标记节点的标签、属性和无混淆特征；
   - 卡片最小公共容器；
   - 动态滚动后新增卡片的插入位置。
2. 保存一份经过脱敏、尽量小的 DOM fixture 到测试目录；不要保存用户账号信息或 Cookie。
3. 新建 Pixiv DOM 适配器，不要继续把站点选择器堆进 `main/index.ts`。
4. 在页面加载后安装一个幂等的 `MutationObserver`：
   - 只检查新增节点及其附近容器；
   - 精确匹配独立的 PR/推广标记；
   - 给整张卡片增加本地命名的隐藏属性或 class；
   - 避免每次 mutation 全量扫描整个文档。
5. 页面切换和软导航后确保适配器仍存在；重复安装不得创建多个 observer。
6. 增加“第一方推广拦截”统计，和网络广告统计分开。

### 止损条件

- 如果只能通过压缩后的随机 class 名定位，不要写死该 class；继续寻找 `data-*`、链接结构、可访问性标签或稳定文本组合。
- 如果无法可靠确定卡片边界，先只隐藏确定性高的节点，不要用宽泛的 `:has(*:contains(PR))` 式逻辑。

### 验收

- 用户截图中的 PR 卡片消失。
- 普通排行榜作品数量和点击导航正常。
- 登录页、收藏按钮、搜索和滚动加载不受影响。
- DOM observer 不引起明显 CPU 占用或无限 mutation 循环。

## P1：持久化远程审查缓存

### 目标

重启应用后，已经由同一模型和同一规则审查过的 Pixiv 图片不再重复推理。

### 实施

1. 按 `ARCHITECTURE.md` 的表结构为数据库增加迁移和测试。
2. 在领域层实现稳定的 `rulesFingerprint`；不能依赖对象插入顺序。
3. 缓存键至少包含规范化 URL、引擎、引擎版本和规则指纹。
4. 先查缓存；命中完整结果时直接决定 allow/block。
5. 只把 `status=complete` 的结果持久化；失败继续失败闭合，但下次允许重试。
6. 增加容量或过期清理策略，并记录命中/未命中统计。

### 验收

- 第一次打开排行榜会运行模型。
- 关闭并重启应用后再次打开，同一批图片不启动重复推理。
- 调整任意元素阈值后旧缓存自动失效。
- 更换模型/标签表版本后旧缓存自动失效。

## P2：拦截占位层与一次性强行查看

### 目标

命中内容不再显示破图或空白，而是显示统一浅色占位卡片、命中原因和明确的“仅本次查看”操作。

### 安全要求

- 强行查看必须是用户对单张作品的明确操作。
- 一次性查看不能写成永久 `allow` 缓存。
- 默认状态仍然不能把原图先渲染到页面再用 CSS 遮住。
- 页面脚本不能调用通用 IPC；交互必须通过受限、可验证的消息通道或主进程控制。

### 技术探针

比较两条路线后再决定：

1. 取消原请求 + Pixiv DOM 适配器注入占位层。
2. 将请求重定向到本地安全占位资源，并维护 URL 到判定原因的映射。

优先选择不会造成原图闪现、不会破坏 Pixiv 虚拟列表复用、且能在软导航后恢复的方案。

## P3：性能优化

1. 给视觉进程增加 `ready/health` 握手，解决冷启动状态不透明的问题。
2. 记录下载、排队、推理和页面恢复四段耗时，而不是只有总计数。
3. 使用持久化缓存消除重复推理。
4. 评估通过自定义协议或受控本地响应复用已经下载并审查的字节，消除双重下载。
5. 保持模型串行或明确受控的低并发；Python 服务当前按行串行处理请求。

## P4：主进程模块拆分

按 `ARCHITECTURE.md` 的目标目录拆分。每移动一个策略，先保留或补齐单元测试；不要改变行为与重构同时进行。

## 推荐提交顺序

1. `feat(explore): hide first-party Pixiv PR cards`
2. `feat(cache): persist remote image review decisions`
3. `feat(explore): render guarded placeholders and one-shot reveal`
4. `perf(explore): expose vision readiness and reuse reviewed bytes`
5. `refactor(explore): split controller and policies from main process`
