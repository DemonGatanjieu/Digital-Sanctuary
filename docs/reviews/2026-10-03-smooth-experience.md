# 流畅体验审核与改动

日期：2026-10-03。基线：`d7da135`。目标是在现有图库、探索、创作、设置四条路径中减少等待与重复操作，让图片浏览保持连续。本轮没有扩充顶层导航。

## 已落地的行为

| 问题 | 改动与用户效果 |
| --- | --- |
| 快速输入搜索、加载下一页与刷新可能互相覆盖 | 单一查询控制器管理请求代次与同步分页锁；非空搜索防抖 180ms，过期结果和错误不会替换当前查询 |
| 切到设置后返回图库丢失已加载内容与位置 | 按图库模式保存滚动位置；返航复验已加载范围，最多 200 件一批读取，同时更新相册、画师等元数据；原生网页保存的新作品也会出现 |
| 新增一页导致已有卡片一起渲染 | 作品卡片使用正常浅比较 memo 和稳定回调；操作仍读取最新选择状态，重复提交防护及失败反馈保留 |
| 查询提前聚合整库资产，缩略图路径检查扫描全表 | SQLite 先确定当前页，再读本页资产/相册摘要；补充部分索引。导入返回记录按 ID 查询，避免每张新图读完整图库 |
| 搜索会重启补图循环；重叠请求重复生成 | 后台补图循环独立于搜索；同一数据库实例共享进行中批次，缓存缺失迭代找到本批数量便停止；降低可见封面的刷新频率 |
| 设置、整理、创作代码随首屏一起加载 | 页面及部分弹窗按需加载，首屏主 JS 从 1,061.85kB 降到 909.01kB；这些页面代码在需要时加载，原有草稿保留机制继续生效 |
| 两套大图入口的拖动、缩放和焦点处理不同 | 共用查看器 hook；坐标以 refs 保存，拖动每帧至多更新一次 transform；滚轮以鼠标落点缩放，1:1 根据原图像素计算 |
| 全集同步预解码占用内存并拖慢进入画册 | 画册只异步预取邻近展对的最多四张额外图片；大图只预取前后两页，跳过已知超大原图；省电档停用预取，退出释放引用 |
| 输入抽屉时底层快捷键仍可能工作；快速切页会显示旧响应 | 大图、雷达/透视抽屉与弹窗逐层拥有焦点、键盘和退出动作，抽屉开启时禁用背景翻页；透视请求按目标/页管理代次，过期成功、错误和 loading 不会更新当前页面，相同目标重渲染不重复推理；HUD 获焦保持可见，加载失败有可见反馈 |
| 常用能力需要记住页面位置 | 新增统一快捷操作面板，可搜索“导入 / 相册 / 模型 / 搜索图库”等操作；探索原生页面也能打开，取消后恢复原生键盘焦点 |

## 新增快捷键

| 场景 | 快捷键 | 操作 |
| --- | --- | --- |
| 应用主界面、探索网页 | Ctrl+K | 快捷操作；可用上下键选择、Enter 执行、Esc 取消 |
| 应用主界面 | Ctrl+O | 导入本地图片 |
| 全部作品 | Ctrl+F | 聚焦图库搜索 |
| 应用主界面 | Ctrl+1 / 2 / 3 / 4 | 图库 / 探索 / 创作 / 设置 |
| 大图 | ← / →、Home / End | 上下页、首末页 |
| 大图 | 1、0 / R、+ / − | 原始像素、适应窗口、缩放 |
| 大图及抽屉 | Esc | 退出最上层界面 |

侧栏有可见“快捷操作”按钮，无需记快捷键。弹窗/抽屉开启时不执行背景导航。原生探索只桥接 Ctrl+K，其余组合键仍归网页。

## 性能证据与范围

数据库夹具含 10,000 件作品、50,000 张资产，每次返回 60 件；保存时间首屏查询中位数 **46.58ms → 3.22ms**，末页 **63.04ms → 6.31ms**。缓存目录丢失且请求 6 张缩略图时，队列选择中位数 **1,575.63ms → 0.30ms**。完整方法、其他排序与边界见 [数据库性能实测](../research/2026-10-03-library-query-performance.md)。这些数字不包含图像解码和界面绘制。

`scripts/benchmark-library.mjs` 使用临时 10,000 件元数据图库，36 次滚动触发分页，没有真实图片解码。基线和优化后的记录：

| 指标 | 基线 | 优化后 |
| --- | ---: | ---: |
| 首批作品就绪时间 | 585ms | 570ms |
| 滚动后加载卡片数 | 1,500 | 2,160 |
| 滚动观察中的长任务数 | 32 | 11 |
| 长任务累计 / 最大耗时 | 2,571 / 145ms | 681 / 102ms |
| Renderer 脚本耗时 | 2,950.1ms | 254ms |
| 测量时 JS 堆 | 14MB | 15MB |

脚本对每一步等待 45ms 后采样下一次 requestAnimationFrame，这不是连续帧率测量。自动分页得到的卡片数不同，新脚本还包含返航检查，以上结果是同机场景观察，不作为固定加速倍数或真实图片 60fps 承诺。此前优化后一次运行加载 1,740 张卡片，长任务累计 355ms，JS 堆 12MB；表中为最终构建的一次运行。冷启动、系统缓存、原图尺寸和显示档位会影响结果。数据落点是已消除明显重复渲染和全库聚合，而非所有渲染成本都已消除。

真实 Electron 查看器使用自造横竖多页 PNG：100 次同帧指针输入在两个入口都只有一次 transform 写入；1:1 以原图宽度/布局宽度验证，HUD 显示 100%；拖动与滚轮没有改变背景滚动位置。预取仅针对邻页且退出后引用数为零，省电档不新增预取对象。

## 验证与使用

- `npm.cmd run verify`：类型检查、62 个 Vitest 文件 / 285 项测试、9 项 Python 单测及生产构建通过。
- `node scripts/smoke-navigation.mjs`：22 项检查通过，覆盖快捷面板、中文输入法、搜索焦点、返回位置及新增作品、五类设置草稿、无模型创作入口、三档显示策略、主题与原生探索生命周期。原生快捷键使用回环 Node Inspector 发送 Electron host input，因为 CDP 键盘事件跳过 `before-input-event`。
- `node scripts/smoke-viewer.mjs`：两个入口、900px 小窗口、全貌、缩放与拖动、分页、抽屉焦点、预取释放、默认相册/画师启动；同时检查 memo 卡片的喜欢/撤销、选择模式及真实失败加入相册，避免假成功通知。透视抽屉另外用隔离进程中的受控乱序 IPC 响应验证旧页不会覆盖新页，并检查输入法组合期间 Esc 不关闭抽屉。
- `node scripts/benchmark-library.mjs`：1 万件元数据图库分页与返航检查。

所有烟测使用临时数据库与隔离用户数据；不下载用户作品、不修改真实图库或安装模型。截图位于忽略的 `.tmp/navigation-smoke/` 和 `.tmp/viewer-smoke/`。构建已更新，根目录启动器会运行最新源码；本轮未重建安装包。

## 仍有成本的路径

相册/画师视图仍通过旧兼容 API 读取整库资产；这轮优化了预取和重复渲染，没有改写其分页契约。字节数排序仍需要汇总全部候选的资产体积。全部缓存有效或缺失项位于队列尾部时，缩略图检查仍可能遍历较多记录。

缩略图编码仍使用既有串行小批及原子缓存落盘。隔离 Windows 探针显示 Electron Shell 缩略图的 Promise API 返回前仍有同步成本，并会改变小图上采样、EXIF 方向和目录处理语义，因此没有直接替换；未来若继续优化，应采用可隔离的编码任务并保留当前输出语义。
