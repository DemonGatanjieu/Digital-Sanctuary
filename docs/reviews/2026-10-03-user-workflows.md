# 用户操作路径快速审核与整合

日期：2026-10-03。范围：当前源码、未提交改动、导航与设置、图库到整理及创作的操作路径。本次是产品入口与关键流程审核，不代表对所有后端模块的完整审计。

## 审核结论

项目已经具备浏览、下载、本地管理、标签分析、画评、对话与生成桥接等能力。主要认知负担来自技术模块直接成为导航项，以及设置按开发顺序堆叠。整合原则是先让用户选择要做的事，再在对应位置提供工具和配置。

| 原问题 | 用户影响 | 已落地的调整 |
| --- | --- | --- |
| 画廊、智能工坊、模型中心、本地灵感台、探索、设置六项并列 | 新用户要先理解模型与工坊的区别 | 主入口收敛为图库、探索、创作、设置；整理属于图库，模型属于设置 |
| 所有设置模块在一页依次挂载 | 主题和字体挡在存储、规则之前，外部连接也过早出现 | 五个用途分组，初次访问才挂载；已访问组隐藏并保留草稿，默认打开图库与存储 |
| 首次导入文案声称自动审查 | 与可信本地资产及显式分析语义冲突 | 导入显示“正在导入”；空图库同时提供导入与探索入口 |
| 多选后的分类分析进入排查页 | 用户需要重新寻找任务入口 | 直接进入分类建议并带入选中范围，不自动启动任务 |
| 恢复默认位置使用完整默认偏好对象 | 排序、密度和默认视图一起被重置 | 只清除下载目录，保留浏览偏好 |
| 侧栏常驻显示引擎名、提供者与三档性能缩写 | 技术状态挤占日常导航；探针就绪可能显得保护有效 | 性能配置归入外观；侧栏显示可点击的探索保护状态，探针不会呈现绿色就绪 |
| 多页面共用主滚动容器 | 从长设置页切走可能停在新页面中部 | 切换页面或设置组时回到顶部 |
| 统计卡片和换肤罗盘占据图库首屏 | 作品列表被推到窗口下方 | 统计改为一行；换肤罗盘归入外观设置，作品横幅缩小 |
| 创作页内宽度按完整窗口估算 | 小窗口聊天区产生横向滚动，模型安装入口远离首屏 | 响应布局按侧栏占用调整；没有模型时首屏显示安装入口，并禁用发送与重新生成 |
| 无保护旁路开启后只按引擎状态显示侧栏提示 | 模型恢复后可能误报保护已就绪 | 无保护会话提示优先，点击可回探索恢复保护 |
| 探索保存路径过长时撑宽侧栏 | 小窗口出现横向滚动，下载操作被挤出 | 限制网格最小列宽并让路径省略，保留完整操作按钮 |

## 能力位置

| 想做的事 | 入口 |
| --- | --- |
| 导入、找作品、看大图、分相册、按画师浏览 | 图库 → 浏览作品 |
| 按已分析标签筛选、批量处理、获取分类建议 | 图库 → 整理与分类 |
| 查看画面元素、整理生成提示词、运行雷达画评 | 作品大图 → 原有元素透视 / 雷达入口 |
| 浏览 Pixiv、保存作品或下载收藏 | 探索 |
| 带图聊天、小说片段、角色与世界观设定 | 创作 |
| 保存位置、迁移、数据库备份、默认浏览方式 | 设置 → 图库与存储 |
| 主题、头像、字体、显示档位与动态效果 | 设置 → 外观与显示 |
| 拦截规则、个人偏好、单图规则测试 | 设置 → 探索保护 |
| 安装或切换识别与评论模型 | 设置 → 本地模型 |
| 外部画评服务、ComfyUI 连接与模板 | 设置 → 外部连接 |
