# 图片优先重设计

- 状态：进行中（整顿期唯一路线）
- 开始：2026-10-09，分支 `redesign/image-first`
- 规范：根目录 `AGENTS.md`

## 目标

1. **核心是图片**：图库首屏见图，界面退为画框。
2. **降低门槛**：一件事一个入口；对用户只讲“作品 / 相册 / 画师”。
3. **乱中立序**：一套设计变量和共享组件；CSS 分层；只减不增。

## 已定决策

| 问题 | 决定 | 理由 |
|---|---|---|
| 配色 | 中性灰阶 + 单一强调色；默认主题跟随系统浅色 / 深色 | 彩色界面与图片争夺注意力 |
| 其余三套主题 | 保留（只覆盖变量），不再单独调样式 | 维护成本低，删除收益小 |
| 启动页 | 直接进入图库；“开始”移出主导航，点左上角标志仍可进入 | 首页四张卡片与侧栏重复 |
| 侧栏 | 64px 图标栏：图库、整理、探索、创作；底部为任务、快捷操作、设置 | 原侧栏宽 250px、常驻、每项两行说明 |
| “浏览 / 整理”标签 | 取消，“整理”成为一级入口 | 省掉一整行 |
| 图库头部 | 一行工具条：范围（作品 / 相册 / 画师）· 搜索 · 筛选 · 排序 · 选择 · 导入 | 原头部叠了约 11 层 |
| 横幅、统计、说明文字 | 从图库移除 | 占据首屏，信息价值低 |
| 常用筛选与保存筛选 | 收进“筛选”弹层；生效条件显示为可逐个移除的标签 | 默认不占空间 |
| 网格 | 按原比例的等高行，无卡片框；悬停显示标题、喜欢与页数 | 图片本身就是卡片 |
| 卡片操作 | 改名、复制、加入相册、移出相册进入右键菜单；直接拖动图片即可拖出 | 原来每张卡常驻 6 个控件 |
| 大图 | 纯黑背景，工具自动隐藏，信息在右侧抽屉 | 与图库风格统一 |
| 装饰组件 | 雷达 HUD、水族馆、罗盘、英文装饰标题逐步移除或收进高级入口 | 不装饰 |

## 安全审计（第一轮，2026-10-09）

| 项目 | 结论 | 处理 |
|---|---|---|
| 渲染进程隔离 | 主窗口 `sandbox` + `contextIsolation`，无 `nodeIntegration`；网页探索无 preload | 保持 |
| `sanctuary-image://` | 只放行数据库登记的作品、缩略图、头像路径；探索会话用独立分区，无法访问 | 保持 |
| `sanctuary-font://` | 只接受 `custom/<ID>`，ID 白名单 | 保持 |
| API 密钥 | 系统 safeStorage（DPAPI）加密落盘；不可用时只存内存 | 保持 |
| IPC 来源 | 大多数处理器不校验调用方 | **已修**：除探索页 4 个通道外，所有 invoke 只接受主窗口主框架（`ipc-sender-guard.ts`） |
| 主窗口导航 | 只拦截新窗口，未拦截页面跳转 | **已修**：`will-navigate` / `will-redirect` 只允许应用自身页面；禁止 `<webview>` |
| CSP | 渲染页无内容安全策略 | **已修**：生产构建注入 CSP（只允许打包脚本；图片限本地协议、data、https 头像） |
| 保存目录 | 渲染进程可把下载目录改成任意路径 | **已修**：渲染进程只能保留或恢复默认，新目录必须经原生选择框 |
| `color-scheme` | 页面声明为纯深色 | **已修**：`light dark` |

后续可做：对 `registerIpc()` 中接收 ID/查询对象的处理器逐个补齐结构校验（多数已有 `parse*` 函数）；检查主题包 zip 导入与模型下载的完整性校验（已有 `secure-zip.ts`，未复审）。
