# 图库快用与后续发现流程

日期：2026-10-08。当前批次只完成图库快用；网站与检索对话是后续设计，不代表已接入。

## 已接入的图库操作

- 作品卡片标题旁常驻“改名”，使用已有作品显示名称接口。支持中文输入法、保存中关闭限制、失败保留输入和刷新失败提示；不改磁盘文件名，多页共用。
- 卡片提供剪贴板复制和明确拖出手柄，多页标明“封面”。大图信息、文件夹与找图结果的单图取用区复用拖出手柄；整件作品仍从多选或信息区复制原图。
- 原生拖放只接受图库作品/页 ID 或当前文件夹会话/项目 ID。主进程重新解析可信文件并检查存在性，只有本地窗口主 frame 能发起。当前 Electron 43.3.0 的 Windows 实现只提供复制或链接，不提供移动。接收软件必须支持文件拖放；其接收成功不能由应用预先保证。
- “更换横幅”使用原生文件选择器，检查格式、32 MB 和 3,200 万像素限制，生成不超过 1,600×900 的 JPEG，独立保存到 `library.banner.v1` 偏好。不引用原路径，不加入图库、不启动识别。取消和失败保留上一张，支持恢复自动精选；关闭氛围图或使用省电档时仍能找到更换入口。
- 普通图库提供“全部保存方式 / 图库保存 / 外部引用”，卡片同时显示归属。条件进入数据库查询、总数、页数、分页和保存筛选；切换条件会失效旧分页响应。筛选不改变文件归属。

本地导入当前仍是外部引用，探索下载与生成回收是应用保存。后续优先补“复制到图库保存 / 保留原位置”导入选择，以及外部引用缺失时重新定位。不能用文件位于哪个盘、是否落在自定义目录来猜归属，也不能因有了筛选就自动移动已有文件。

## 后续：把探索做成浏览器式的收图入口

沿用探索页面增加可输入网址/搜索词的地址栏和少量网站快捷入口。用户不用先提供网站清单；Pixiv 继续使用现有专门适配。一般网站先支持浏览与主动收取标准图片，再根据真实需要添加适配器。

用户在图片上选择“加入图库”，预览来源、图片和保存结果后收取。应用保存自己的文件，保留网页地址、图片地址和站点名称，之后可与其他收藏一起筛选、找图和取用。网页打开成功、图片能下载、元素保护可用分别表示，不能把 Pixiv 保护状态套到未适配站点。

实现前需要拆开当前 `isAllowedPixivNavigation`、`i.pximg.net` 资源识别和专用 DOM 适配。远程网页仍不能访问本地图库 IPC；下载从用户实际选中的远程图片开始，验证地址、重定向、响应格式和大小，再原子保存。站点会话凭据只用于对应来源，不转发到任意目标。`blob:`、canvas、登录保护、动态图和高清源解析分别说明支持程度，失败留在原页面重试，不保存空文件或假原图。

## 后续：找图之后继续聊

[EmbeddingGemma 2 官方说明](https://huggingface.co/google/embeddinggemma-2)定义的是多模态向量模型。它把中文和图片变成可比较的向量，适合检索；不能直接生成聊天回答。WD 负责明确元素标签，两者都不替代对话模型，也不表示每张图片已经在导入时识别。

项目现有创作页已能用本地 Gemma / Qwen 携一张参考图对话。下一步把找图结果接到这里，先让用户选中具体图片再讨论，保持现有导航和串行模型队列。无需为了这个流程另装第二个聊天系统。

例如“找几张雨夜街景，说说它们的配色”：先显示有限候选与可点击来源，再把明确选中的实际图片送给能读图的模型。只传标签时应说明“根据识别结果”，不能声称看过图片；只有向量时不能凭空生成画面细节。多图讨论需新增有界多图输入和资源协调，当前单图接口不能直接假装支持整库对话。自然语言条件转换也必须生成可查看的筛选条件，不自动搬动、删除或改名。
