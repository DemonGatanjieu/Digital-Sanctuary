# 图库快用、网站收图与检索后讨论

日期：2026-10-08。图库快用之后，本轮已接通导入保存方式、外部重新定位、普通网站收图与最多四图讨论。现有安装器尚未重打。

## 图库直接中文找图

图库主页搜索框默认“搜画面”，输入描述并按回车即可；首次自动扫描当前筛选范围并建立内容索引，之后复用未变化的图片，不需要到整理页载入范围。搜索位于横幅前，进度/停止/失败重试在原处。相册、画师、喜欢、保存方式等筛选与名称查询共用 SQL 条件；更改范围收起旧结果，提交后按新范围搜索。名称、画师和 ID 在同一个框切换搜索方式即可。

结果仍是普通图库卡片，多页作品以最匹配的页作为卡片和大图入口；复制、拖出明确针对这一页。每次显示 60 件作品，图库搜索最多 10,000 页，达到上限明确提示未搜索全库。相似程度用于排序，不能当作精确元素识别；精确“需要/排除”仍留在找图与整理。离页任务继续，返航保留输入与已加载结果；清除/切换名称模式会停止旧任务但保留已建立索引。

## 已接入的图库操作

- 作品卡片标题旁常驻“改名”，使用已有作品显示名称接口。支持中文输入法、保存中关闭限制、失败保留输入和刷新失败提示；不改磁盘文件名，多页共用。
- 卡片提供剪贴板复制和明确拖出手柄，多页标明“封面”。大图信息、文件夹与找图结果的单图取用区复用拖出手柄；整件作品仍从多选或信息区复制原图。
- 原生拖放只接受图库作品/页 ID 或当前文件夹会话/项目 ID。主进程重新解析可信文件并检查存在性，只有本地窗口主 frame 能发起。当前 Electron 43.3.0 的 Windows 实现只提供复制或链接，不提供移动。接收软件必须支持文件拖放；其接收成功不能由应用预先保证。
- “更换横幅”使用原生文件选择器，检查格式、32 MB 和 3,200 万像素限制，生成不超过 1,600×900 的 JPEG，独立保存到 `library.banner.v1` 偏好。不引用原路径，不加入图库、不启动识别。取消和失败保留上一张，支持恢复自动精选；关闭氛围图或使用省电档时仍能找到更换入口。
- 普通图库提供“全部保存方式 / 图库保存 / 外部引用”，卡片同时显示归属。条件进入数据库查询、总数、页数、分页和保存筛选；切换条件会失效旧分页响应。筛选不改变文件归属。

本地导入确认页默认“复制到图库保存位置”，副本进入当前根目录 Imports/随机目录，保留原文件名；也可明确选择“保留原位置，仅加入图库”。两种归属分别复用重复图片，不把外部记录悄悄升级成副本。原文件均保留，不在导入时运行模型。移动外部原图后，在作品信息中重新定位；已知指纹必须一致，早期无指纹的记录保留名称/相册但清除无法校验的旧分析。保存位置迁移只处理 managed，外部引用维持原路径。

## 已接入：浏览图片网站与主动收图

探索地址栏接受公开 HTTP(S) 网址，也可输入关键词进行图片搜索。用户可保存当前网站为快捷入口，最多 12 个，并就地移除；不增加一级导航。Pixiv 保留原有专用视图、账号会话、规则和作品/收藏下载。一般网站使用无 preload、无本地 API 的独立沙箱视图，页面上明确标记“此站未适配元素拦截”，不沿用 Pixiv 的保护结论；普通视图不放行 Pixiv/pximg，导航回 Pixiv 时仍由保护门控制展示。

普通网页图片上右键“加入图库”，由主进程读取该次实际菜单中的图片地址。验证公开地址/DNS、每次重定向、MIME 和图片签名，限制 30 秒 / 32 MB，排他写入 Web 目录。原图、managed 归属、页面/图片网址、站点标题与保存时间事务入库；重复 managed 内容复核后复用，既有名称和首个来源不覆盖。失败留在当前页显示原因，可重试，不保存空文件或假原图。

标准 HTTP(S) JPG/PNG/WebP/GIF/AVIF 文件可收取，保存网页实际提供的字节；不保证它就是站点隐藏的最高分辨率版本。blob、canvas、SVG、专门登录/防盗链或高清源解析需要后续适配；当前会提示先下载再导入。站点凭据留在对应会话，应用不读取系统浏览器 Cookie，也不提供网页任意文件路径入口。

## 已接入：找图之后继续聊

[EmbeddingGemma 2 官方说明](https://huggingface.co/google/embeddinggemma-2)定义的是多模态向量模型。它把中文和图片变成可比较的向量，适合检索；不能直接生成聊天回答。WD 负责明确元素标签，两者都不替代对话模型，也不表示每张图片已经在导入时识别。

现有创作页复用本地 Gemma / Qwen 视觉对话运行时。图库找图结果选中 1–4 页后点“聊聊所选图片”，主进程重新解析对应资产再打开创作草稿；文件夹点“导入后讨论”，确认保存方式/相册，完成后点击讨论成功导入的图片。临时文件夹授权不会变成永久聊天路径。创作页可逐张追加、替换第一张或逐张移除，最多 4 张，发送前仍能编辑提问。没有安装视觉模型时保留参考图并提供安装入口。

例如“找几张雨夜街景，说说它们的配色”：先显示有限候选与可点击来源，再把明确选中的实际图片送给能读图的模型。只传标签时应说明“根据识别结果”，不能声称看过图片；只有向量时不能凭空生成画面细节。本轮实际向视觉模型传入有序多张图片，模型提示使用图片编号；逐回答来源和 Markdown 保存对应作品/页，不因后续更换参考图改写历史。单图 32 MB / 3,200 万像素、总准备图片 32 MB，多图缩至长边 560，按需使用 8192 上下文，仍共用串行队列与闲置释放。带图提问最多 2000 字；失败清理图片并保留已保存内容。这是用户明确选择的少量图片讨论，不是整库代理。自然语言条件转换也必须生成可查看的筛选条件，不自动搬动、删除或改名。
