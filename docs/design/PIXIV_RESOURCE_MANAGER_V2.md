# 纯净领域 2.0：Pixiv 资源管理器产品设计

- 状态：实施基线
- 设计日期：2026-08-13
- 产品阶段：从技术闭环原型进入可长期使用的桌面产品

## 1. 产品定义

纯净领域不是“套着 Electron 的 Pixiv 网页”，也不只是一个下载器。它是一款本地优先的 Pixiv 资源管理器，由两个互相连接、但信任边界不同的空间组成：

1. **探索空间**：浏览远程 Pixiv，广告过滤与不欢迎元素过滤生效，未知内容先审查后显示。
2. **收藏空间**：管理用户主动保存的可信作品，以作品、作者、分类和时间为主要浏览维度，不因后台模型自动变模糊。

设计目标是让“逛、存、找、整理、回看”形成闭环。高颜值来自图片、排版、空间和环境共同构成的氛围，不来自每个容器都叠加玻璃、渐变和阴影。

## 2. 设计原则

### 2.1 图片是视觉主角

- 图库默认使用低干扰的中性浅色背景，避免背景与大量缩略图争夺注意力。
- 进入作品详情或沉浸查看时，才从封面提取低饱和主色，生成局部环境光、柔和渐变和过渡。
- 环境效果不得改变图片色彩，不把模糊背景冒充图片内容，也不能成为持续 GPU 负载。

### 2.2 美观必须服从操作层级

- 一个区域只允许一个主要强调动作。
- 高频动作直接可见；低频管理动作进入上下文菜单或管理面板。
- 删除、联网补全、模型分析等有副作用的动作不能做成无标签图标。
- 不使用 9px 正文、难以辨认的低对比文字或只有悬浮才知道含义的按钮。

### 2.3 不以“新奇”替代可预测性

按钮可以有更丰富的互动反馈，但基础语义必须符合桌面习惯：

- 点击作品封面：打开作品详情/原图查看。
- 卡片右上角 `···`：打开与该作品相关的动作菜单。
- 复选框或进入选择模式：多选；不把普通单击偷偷改成多选。
- 拖动作品到分类：作为快捷方式；分类菜单仍然保留，保证可发现性和键盘可用性。
- 悬浮动作条只提供“喜欢、加入分类、更多”三个高频入口，不把整套工具塞进卡片。

### 2.4 质量、平衡与节能是显示档位，不是三套产品

用户可以选择渲染档位，但信息架构和操作位置保持一致：

| 档位 | 默认用途 | 环境效果 | 动画 | 缩略图策略 |
|---|---|---|---|---|
| 质量 | 高性能桌面与沉浸欣赏 | 作品详情局部环境光、柔和模糊 | 完整但克制 | 更高分辨率缓存 |
| 平衡（默认） | 日常浏览 | 静态低饱和环境色 | 短过渡 | 标准缓存 |
| 节能 | 电池、低端显卡、大图库 | 纯色表面 | 仅必要状态过渡 | 较小缓存、积极回收 |

`prefers-reduced-motion`、系统节能状态和远程桌面场景可以自动降低效果，但必须允许用户覆盖。

## 3. 信息架构

### 3.1 一级导航

侧栏只保留五个稳定入口：

1. **画廊**：全部作品、最近保存、喜欢和历史。
2. **探索**：嵌入 Pixiv 与下载入口。
3. **作者**：作者封面墙和作者详情。
4. **分类**：用户自建分类与智能分类建议。
5. **设置**：拦截、自定义、显示、性能、存储和模型。

下载与模型任务不占用长期一级导航。它们通过右下角“任务中心”出现；有任务时显示进度，无任务时不占空间。

### 3.2 画廊顶部工具栏

第一行：页面标题、搜索、选择模式、更多。

第二行：

- 视图：作品 / 时间线；
- 类型：插画 / 漫画 / 动图 / 未知；
- 排序：最近保存、Pixiv 发布时间、最近浏览、标题、作者、页数、文件大小；
- 顺序：升序 / 降序；
- 网格密度：舒适 / 紧凑；
- 当前筛选条件以可清除标签显示。

搜索范围包括标题、作者、Pixiv 作品 ID、用户标签和分类。首版使用 SQLite 本地查询，不引入云搜索。

### 3.3 作品级而非页面级浏览

- 图库卡片代表一个作品，多页作品只显示一张封面和页数角标。
- 点击后进入作品详情，页面缩略条用于切换页。
- 页面文件是作品内部资产，不在顶层网格重复占位。
- 顶部统计明确区分“作品、图片页、作者、分类”，不再把图片页叫作品。

### 3.4 作品详情

作品详情由三块构成：

1. 主图片区：适应窗口 / 1:1、翻页、全屏。
2. 作品信息：标题、作者、发布时间、保存时间、类型、页数、来源链接。
3. 操作区：喜欢、加入分类、编辑本地标签、在 Pixiv 打开、更多。

环境光只存在于主图片区周围。信息区保持稳定、可读，不随图片颜色大幅变化。

### 3.5 作者与分类

- 作者卡使用本地头像、代表作品拼图、作品数和最近更新时间。
- 作者详情复用标准作品网格，不再维护第二套卡片逻辑。
- 分类卡使用自定义封面或自动拼图；支持编辑名称、介绍、封面、排序和删除。
- 分类内删除的默认动作是“移出此分类”，而不是删除文件。

## 4. 操作系统

### 4.1 卡片动作

卡片常态只显示封面、标题、作者和必要角标。悬浮或键盘聚焦后显示：

- 喜欢；
- 加入分类；
- `···` 更多。

更多菜单包含：打开详情、在 Pixiv 打开、查看作者、编辑标签、显示文件位置、移出画廊/移至回收站。危险动作与普通动作分隔。

### 4.2 多选与批量操作

- 工具栏“选择”进入明确选择模式。
- 卡片出现复选框，支持 Shift 连选和 Ctrl 切换。
- 底部操作栏显示选中数量，并提供：加入分类、喜欢、模型整理、移出画廊、更多。
- 批量操作完成后提供摘要；可恢复操作提供撤销。

### 4.3 删除与回收站

删除必须体现文件所有权：

- **外部导入文件**：默认“移出画廊”，不删除原文件。
- **应用托管下载**：默认“移至系统回收站”，不直接永久删除。
- **多页作品**：顶层默认处理整部作品；单页删除只在作品管理面板中提供。
- **分类中操作**：第一动作是“移出分类”。
- 数据库记录在文件操作成功后更新；失败时不留下半删除状态。

### 4.4 非跳转型互动

以下互动用于提高效率，但不替代普通按钮：

- 拖动作品卡到侧栏分类，目标分类出现明显接收状态。
- 按住空白处拖出选择框，用于密集网格批量选择。
- 任务中心可展开为抽屉，继续浏览时不阻断页面。
- 作品详情的操作胶囊可以横向展开，不因每个操作跳到新页面。

不使用隐藏长按、双击删除、手势记忆或无法通过键盘完成的核心操作。

## 5. 自定义中心

### 5.1 外观

- 浅色 / 深色 / 跟随系统；
- 强调色（提供经过对比度验证的预设，不允许任意颜色破坏可读性）；
- 显示档位：质量 / 平衡 / 节能；
- 默认页面、默认视图、默认排序、网格密度；
- 动画强度和环境光开关。

### 5.2 元素拦截

- 内置组可启停、调整阈值和动作（模糊 / 隐藏）；
- 用户可新建自定义组：名称、说明、模型标签、标签别名、阈值、动作；
- 提供“使用测试图片预览规则”的沙盒，不直接拿真实探索页做试错；
- 自定义变化会生成新规则指纹，使旧缓存安全失效。

### 5.3 下载与存储

- 托管图库目录；
- 文件命名模板；
- 收藏下载重复策略；
- 原图并发与 Pixiv API 保护保持安全上限，不向普通用户暴露危险的无限并发；
- 缓存大小、缩略图质量和清理入口。

### 5.4 AI 模型与设备

AI 模型选择与显示档位分开：

- 展示模型名称、版本、能力（标签/元素覆盖）、执行设备和最近基准；
- 默认选择经过项目验证的 WD Tagger；
- GPU 初始化失败自动回退 CPU，并给出一次非阻断提示；
- 模型切换产生新的分析命名空间，不错误复用旧结果；
- 模型只参与探索审查和用户显式发起的整理任务，不能自动接管可信收藏。

## 6. 视觉系统

### 6.1 基础气质

关键词：安静、精致、通透、内容优先、日系数字画廊。

- 主背景使用近白中性色，避免大面积蓝紫弥散渐变。
- 蓝色只用于主要动作、选择和链接；状态使用语义色。
- 卡片优先靠留白和轻微层级区分，减少玻璃滤镜和悬浮位移。
- 圆角分三级，阴影分两级，禁止每个组件自行发明数值。
- 使用本地字体或系统字体栈，避免 UI 因 Google Fonts 失败而变化。

### 6.2 按钮层级

- **主要按钮**：每个区域最多一个，实色强调。
- **次要按钮**：中性描边或弱底色。
- **图标按钮**：仅用于通用、可识别动作，并带提示和无障碍名称。
- **危险按钮**：只在确认上下文中使用红色，不常驻卡片表面。
- **分段控件**：只切换同一数据的视图，不用于页面导航。

### 6.3 动效预算

- 常规反馈 100–160ms；页面/抽屉 180–240ms；不使用循环装饰动画。
- 网格滚动期间暂停非必要阴影、环境光和图片缩放。
- 同屏高斯模糊表面不超过一个；大图查看器可以使用一次背景处理。
- 所有动画支持 reduced motion。

## 7. 性能策略

- 网格使用持久化高质量缩略图；原图只在详情/查看器加载。
- 缩略图按作品封面生成，多页不重复解码所有原图。
- 列表查询在数据库完成搜索、筛选、排序和分页，不把全库一次性传给 React。
- 大图库使用虚拟化网格；目标规模至少 10,000 个作品。
- 作者、分类和作品查询返回视图模型，不由 React 每次遍历全库临时聚合。
- 环境色在导入/下载时异步提取并缓存，不在滚动时实时分析图片。
- 任务并发按资源类型隔离：下载、缩略图、视觉推理分别设门，不共享一个无界队列。

## 8. 首轮明确不做

- 不复制系统浏览器 Cookie，不伪装 Google 登录环境。
- 不把完整 Chrome 扩展系统作为产品依赖。
- 不自动启动全库模型整理。
- 不做不可恢复的直接永久删除。
- 不以瀑布流特效、大量 3D 动画或持续背景模糊换取“高级感”。
- 不在数据模型未升级前补一套临时的页面级排序和删除。

## 9. 设计验收标准

1. 新用户能在一分钟内理解“探索”和“本地收藏”的区别。
2. 保存一个多页作品后，图库只增加一个作品卡，详情能看到全部页。
3. 搜索、排序、筛选、多选和删除不依赖隐蔽手势。
4. 任意危险操作都明确展示影响范围与文件所有权。
5. 质量、平衡、节能切换后布局不变化，只改变渲染成本。
6. 10,000 作品数据库中，首屏不需要加载全部原图或把全部记录传给前端。
7. UI 在字体、网络或模型不可用时仍保持稳定布局。
