# 产品与交互指导原则

- 状态：已采用，适用于后续产品设计、实现与评审
- 更新日期：2026-10-04
- 来源：用户提供的七项通用经验，并结合本项目的任务入口、本地图库和模型能力边界细化

纯净领域让用户从“想做什么”开始，在操作发生的地方理解工具、得到反馈并完成任务。新增能力和调整界面都以这些原则评审；具体实施范围由当前用户请求和任务计划确定。

## 七项原则

| 原则 | 落到产品里怎么做 |
| --- | --- |
| **说人话** | 按钮说明会执行的动作；提示和报错说明发生了什么、影响什么、接下来能做什么。内部引擎名、协议、原始标签和堆栈放到详情，日常界面使用用户理解的词；选择模型时保留实际模型名称和用途说明。未知原因如实说明，不把模型失败写成命中规则，也不把零命中写成全部检查通过。 |
| **按任务组织功能** | 用户在哪里做事，相关工具就在哪里出现。探索中调整元素规则和识别模型；整理中选择范围、查看结果并处理。导入的分类、重复和冲突若进入实施，应在导入流程内解决；设置保留全局偏好与低频管理，复用同一份配置，避免多个入口保存不同真值。 |
| **复杂度逐步展开** | 常用操作直接可见，默认值支持日常使用；高级选项按需展开，入口名称说明里面有什么。精确阈值、原始标签、连接参数和诊断不占首屏。折叠不能藏起当前范围、关键副作用、失败状态或必需操作。 |
| **界面有层级、有一致性** | 每个操作区域突出当前主动作，次要管理动作收敛。相同功能使用一致的命名、样式和行为，复用字体、间距、图标、主题令牌与共享控件。窄窗口、深浅主题、缩放和长中文下仍应读得清、点得到；遮罩和原生探索网页不能挡住操作。 |
| **同时方便人和智能体操作** | 使用语义明确的按钮、标签和稳定的可访问名称；加载、忙碌、成功、失败、禁用原因与选择状态可识别，不能只靠颜色或动画表达。键盘和焦点归属清楚。高频任务提供简短指南，随入口变化同步维护；自动化标识不得承担用户说明，也不能绕过正常确认与权限边界。 |
| **引导用户开始做事** | 首页用“今天想做什么”提供少量具体任务，点击直达；空状态给出下一步。首次需要理解某项操作时再提供局部引导，允许跳过和重新查看。熟悉用户可通过侧栏、快捷键和快捷操作直接进入，不反复强制观看教程。 |
| **让反馈成为操作的一部分** | Bug 和建议入口应容易找到，失败现场能进入反馈流程。自动整理必要的版本、当前页面和错误摘要，用户补充实际操作与预期结果；发送前可预览、删减。提交是否成功要明确，失败保留填写内容，避免用户重新描述。 |

## 实施边界

- **保持流畅、及时和真实的状态。** 点击后及时显示响应，长任务有进度或明确的等待状态；能取消的任务提供取消入口。分页、分析与批处理使用有界资源，旧请求不能覆盖新范围或新页面。动画服务于理解，性能档位与减少动画偏好保持功能可达。
- **让用户知道并决定实际变化。** 预览说明影响范围，批量操作区分成功与失败，并保留失败项供重试；能撤销的操作提供恢复路径。探索规则用于本地整理时先列出命中结果，入册或移除由用户选择，继续遵守托管文件与外部导入的不同处理语义。
- **反馈遵守本地优先。** 自动整理上下文不等于自动发送；用户确认后才发送。版本与页面之外的数据按需要选择，不默认附带原图、完整本地路径、完整聊天内容或登录凭据；截图和日志应允许预览与去除敏感信息。
- **按实际任务落实原则。** 通用原则不是新增所有相关功能的施工授权。首页和探索规则整理已落地；导入冲突处理、首次遮罩引导和反馈流程等例子仍需按各自任务设计与验收，不能仅凭本文宣称已实现。

## 设计与交付检查

对受影响的任务路径检查以下问题，并在评审中记录必要的证据：

1. 用户能否从入口判断用途，找到主操作，并知道下一步会发生什么？
2. 相关工具是否在任务发生处可达，多个入口是否共用相同配置和数据语义？
3. 首屏是否能完成常用任务，高级选项是否找得到，当前范围与副作用是否清楚？
4. 空、加载、成功、失败、部分失败和取消等适用状态是否有准确反馈及可行的下一步？
5. 窄窗口、主题、缩放、键盘、输入法和最上层弹窗是否保持操作可达、焦点正确？
6. 慢请求、范围切换、返回页面和重试是否保留必要上下文，且不会显示旧结果或重复执行？
7. 引导和反馈若在本次范围内，是否可跳过或重看、发送前可检查、失败后保留输入？

验证范围应与改动匹配；共享控件和交互边界需覆盖受影响的入口。原则评审不能替代项目要求的类型检查、测试和构建，也不要求为每次小修改重做全产品。
