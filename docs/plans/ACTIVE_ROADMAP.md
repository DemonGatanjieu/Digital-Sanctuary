# 现行实施路线

- 状态：唯一现行计划
- 基线：`36600de feat: complete trusted Pixiv library stage`
- 最近校准：2026-08-11

当前阶段已经完成探索、可信下载和本地浏览闭环。下一阶段优先实现“显式模型整理”，而不是继续扩大探索拦截或广告规则。每个阶段都应单独测试和提交。

## P0：先分离“模型分析”与“展示信任”

### 目标

模型可以为本地图片生成标签和分类建议，但不能覆盖用户主动下载形成的可信 `allow` 决策。

### 实施

1. 为图库分析结果设计独立持久化结构，至少包含：
   - artwork ID 或稳定内容哈希；
   - engine、engine version；
   - assessment JSON；
   - 分析时间和状态。
2. 不要把整理结果直接写回现有 `artworks.decision_json`；该字段当前同时承载探索/导入决策和用户信任，需要保持兼容。
3. 为“标签建议”“候选分类”“用户已确认分类”定义不同类型，自动建议不能伪装成用户操作。
4. 同一文件、同一引擎版本的完整分析允许复用；失败和取消不形成永久成功缓存。
5. 先写数据库迁移与单元测试，再接 UI。

### 验收

- 对可信作品运行模型后，画廊仍清晰展示，原 `allow` 决策不变。
- 重启后完整分析可复用；更换引擎版本后不会错误复用旧结果。
- 失败或取消任务不留下“已完成”的标签建议。

## P1：显式模型整理最小闭环

### 目标

用户明确选择范围、预览任务、运行模型并查看建议；首版不自动执行分类变更。

### 推荐范围

1. 画廊增加“模型整理”入口，默认不运行。
2. 首版范围支持：当前作品、当前作者、手动选中图片和全库；必须在开始前显示图片数量。
3. 任务面板显示等待、分析中、完成、失败和取消数量；尚未开始的任务可以取消。
4. 推理保持单路或经基准确认的低并发。下载并发与模型并发必须继续分开。
5. 结果页展示模型标签、置信度、来源版本和候选分类；用户确认后才写入分类关系。
6. 任务结束后不弹出大量逐图提示；用摘要和可展开失败列表呈现。

### 止损条件

- 如果必须覆盖用户信任决策才能复用现有 UI，先停下补 P0 数据边界。
- 如果全库任务会在界面启动时自动恢复并立刻占满 GPU，先实现“暂停等待用户继续”，不能后台偷偷运行。
- 如果分类建议无法解释来源标签，首版只显示标签，不自动建议分类。

## P2：作者浏览与元数据质量

1. 为缺少 Pixiv 来源的旧记录提供显式补全提示，不在应用启动时批量联网。
2. 作者封面墙继续使用本地代表作品；若以后加入头像，必须缓存到应用托管目录，不能依赖每次打开时远程热链。
3. 作者页保持本地浏览语义；若提供“在 Pixiv 打开作者”，使用受限站内导航或明确外部打开，不把远程页面伪装成本地数据。
4. 大图库性能以实测为准。原图懒加载仍不足时，先记录首屏、解码和内存数据，再决定是否生成可选缩略图。

## P3：拆分主进程组合根

按 `ARCHITECTURE.md` 的目标边界小步迁移：

1. `download/`：Pixiv API、原图抓取、并发门和下载状态。
2. `library/`：导入、可信入库和模型整理协调。
3. `explore/`：视图生命周期、导航策略、网络策略和审查协调。
4. 每次只移动一个行为，先保留或补齐测试；不要在同一提交里同时重构和改变产品逻辑。

## P4：冻结功能的重新启用门槛

### 视口驱动审查

只有满足以下条件才允许把 `ENABLE_VIEWPORT_REVIEW` 改为 `true`：

- 本地 fixture 覆盖 preload 启动、图片发现、IntersectionObserver、候选 IPC、队列、结果回传和图片重载。
- 放行图片的 `naturalWidth > 0`，阻挡图片不会短暂清晰闪现。
- 真实 Pixiv 快速滚动回归中不存在“所有图片永久保护态”。

### 第一方广告美容过滤

- 不再使用 `PR` 文本子串、链接域名向上猜祖先或大容器图片数量启发式。
- 优先评估单一 `onBeforeRequest` 下的标准规则引擎；完整 Chrome 扩展不作为默认依赖。
- 没有稳定 fixture 和普通作品负例之前，不恢复第一方美容规则。
