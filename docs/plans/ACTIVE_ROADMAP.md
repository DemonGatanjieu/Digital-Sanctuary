# 现行实施路线：纯净领域 2.0 产品化重构

- 状态：唯一现行计划
- 设计基线：`docs/design/PIXIV_RESOURCE_MANAGER_V2.md`
- 工程基线：`docs/design/DATA_AND_ARCHITECTURE_V2.md`
- 最近校准：2026-08-14

现有版本已经完成“探索 → 过滤 → 下载 → 本地查看”的技术闭环，但图库仍是页面级原型。下一阶段暂停扩张 AI 整理，优先建立作品级数据、日常管理能力和稳定设计系统。每个阶段单独迁移、测试、构建、提交和验收。

## P0：设计冻结与回归基线

1. 以 2.0 产品设计和数据设计作为后续实现依据。
2. 为当前 6 页 / 5 作品 / 3 作者样本建立迁移前基线。
3. 补充大图库合成 fixture，不用真实账号数据做性能测试。
4. 记录当前下载、探索、作者头像、大图查看器的回归清单。

验收：后续迁移能证明没有破坏既有下载、信任边界和本地文件。

## P1：作品级数据模型与安全迁移

1. 新增 `works/assets`、作品级分类关系、偏好和必要索引。
2. 编写幂等迁移、数据库备份和失败回滚测试。
3. Pixiv 多页聚合为一个作品；外部导入每张成为一个 local work。
4. 新下载双写新模型，暂不删除旧结构。

验收：作品数与图片页数分开；旧图库、分类、作者和路径全部可追溯。

## P2：图库查询与基础产品能力

1. 增加数据库级搜索、筛选、排序和分页。
2. 默认窗口改为约 `1440 × 900`，安全记忆窗口状态。
3. 画廊改为作品卡；支持保存时间、发布时间、标题、作者、页数、大小排序。
4. 增加类型筛选、搜索、网格密度和默认视图偏好。

验收：10,000 作品 fixture 不全量传给 React；多页作品只显示一个卡片。

## P3：管理能力与安全删除

1. 多选、Shift 连选、批量分类和喜欢。
2. 分类名称、介绍、封面、排序、移出作品和删除完整 CRUD。
3. 删除预览区分托管文件与外部索引；托管文件进入系统回收站。
4. Toast、撤销和逐项失败摘要替换原生 `prompt/confirm/alert`。

验收：分类移除不误删文件；外部导入默认不碰原文件；危险操作范围清晰。

## P4：设计系统与环境视觉

1. 拆分 `App.tsx`，建立按钮、菜单、对话框、Toast、分段控件和设计令牌。
2. 去除远程 Google Fonts，使用本地/系统字体。
3. 减少全局玻璃拟态和持续 GPU 合成；作品详情加入缓存的低成本环境色。
4. 实装质量 / 平衡 / 节能显示档位，并支持 reduced motion。

验收：三个档位布局与操作一致；节能模式无持续环境模糊；按钮层级统一。

## P5：缩略图与大图库性能

1. 建立持久化缩略图任务与缓存版本。
2. 虚拟化作品网格；原图只在详情加载。
3. 建立 1,000 / 10,000 作品的首屏、滚动、内存和解码基准。
4. 下载、缩略图、视觉推理使用独立并发门。

验收：滚动期间不批量解码原图，不因环境效果持续拉高 GPU。

## P6：自定义中心

1. 外观、默认视图/排序、网格密度、性能、存储偏好。
2. 用户自定义元素组、标签、别名、阈值和动作。
3. 测试图片规则沙盒；规则变化正确失效远程审查缓存。
4. AI 模型与设备选择页只展示验证过的引擎和能力。

验收：自定义数据持久化、可恢复默认值，不改变探索与可信下载边界。

## P7：显式模型整理

在作品实体、批量选择和任务中心稳定后再实现：

1. 分离模型分析与展示信任。
2. 用户明确选择当前作品、作者、分类、选中项或全库。
3. 预览数量、任务可取消、结果可解释、分类建议需确认。
4. 不自动覆盖用户信任，不在启动或滚动时偷偷运行。

## P8：主进程模块化与发布收尾

1. 按 `window/library/download/explore/analysis/ipc` 小步拆分主进程。
2. 清理兼容结构前提供数据库备份、迁移版本和恢复文档。
3. 完整可访问性、键盘、错误恢复和打包安装验收。

## 推荐提交顺序

1. `feat(database): add work and asset schema`
2. `feat(database): migrate legacy artwork pages`
3. `feat(library): query works with search and sorting`
4. `feat(window): persist safe window state`
5. `feat(gallery): render work-level library shell`
6. `feat(library): add selection collections and safe deletion`
7. `refactor(ui): introduce desktop design system`
8. `feat(library): add thumbnail pipeline and virtual grid`
9. `feat(settings): add appearance performance and custom rules`
10. `feat(analysis): add explicit model organization jobs`

## 止损条件

- 数据迁移不能幂等或无法回滚时，不切换生产读取。
- 删除流程无法区分托管与外部文件时，不提供文件删除。
- 新 UI 仍依赖全库 `listArtworks()` 时，不宣称大图库性能完成。
- 显示档位改变功能位置或安全语义时，退回统一布局。
- 模型整理必须覆盖用户信任才能工作时，先修数据边界。
