# 本地 AI 自由工作台与安全小组件工坊

- 状态：方向设计，尚未进入整包实施
- 日期：2026-08-30
- 前置基础：本地灵感台、Gemma/Qwen 本地运行时、画廊参考图、按对话模型选择
- 与 Anomalous 的关系：完全独立；不等待、也不猜测 Anomalous 接口

## 1. 想解决什么

本地模型已经能读图、聊天和辅助创作，但目前仍像几个固定按钮，用户不容易自由发挥它的能力。

后续目标不是堆更多生硬入口，而是把灵感台逐渐变成一个可组合的本地 AI 工作台：用户可以选择模型、给模型设定临时身份、带入可信素材，并把常用结果整理成可重复使用的小工具。

## 2. 产品原则

1. **先有可理解的玩法，再开放底层参数**：默认仍使用“严谨 / 均衡 / 放飞”和“简短 / 标准 / 详细”；高级参数藏在可选的进阶抽屉中。
2. **一次对话一次上下文**：模型、角色说明、参考图和素材包属于当前工作区，不偷偷影响六维画评、探索过滤或其他会话。
3. **本地优先且有边界**：模型只能读取用户明确加入的画廊图片和文本素材，不能自行遍历磁盘。
4. **小组件生成配置，不生成任意代码**：AI 输出经过 JSON Schema 校验的组件描述，程序用内置组件渲染；禁止 `eval`、任意 HTML、动态脚本和未授权网络请求。
5. **所有 AI 产物都可预览、撤销和删除**：生成失败只影响当前草稿，绝不替换稳定组件。

## 3. 灵感台可以逐步开放的玩法

### P1：对话工作区增强

- 自定义“这次让模型扮演什么”：例如小说编辑、角色设定助手、提示词整理员、画面讲解员。
- 保存为个人玩法卡，下次一键复用；玩法卡只包含文字指令与生成档位。
- 一次加入多张本地画廊参考图，并明确显示模型实际收到哪些图片。
- 将回答导出为 Markdown、提示词预设或本地便笺。
- 显示本轮使用的模型、耗时和是否携图，不暴露难懂的运行日志。

### P2：可信素材包

- 用户显式建立“角色资料”“世界观资料”“写作片段”等素材包。
- 每次只选择少量素材送入模型，提供预计上下文占用提示。
- 素材包有数量、单项大小和总字符上限；超限时让用户选择，而不是静默截断重要内容。
- 暂不做自动扫描整个画廊、整个文件夹或无限长期记忆。

### P3：任务链

- 使用固定、安全的步骤组合，例如“读图 → 提取元素 → 写场景 → 整理提示词”。
- 每一步展示输入与结果，用户确认后再进入下一步。
- 不允许模型自行调用任意系统命令；可用动作必须来自软件维护的白名单。

## 4. AI 小组件工坊是否可行

可行，但第一版必须是**声明式小组件**。

用户可以用自然语言提出：

- “做一个每天随机展示三张收藏作品的卡片。”
- “做一个写作 25 分钟、休息 5 分钟的计时器。”
- “做一个最近常见标签的柔和词云。”
- “做一个当前本地模型状态和显存建议的小面板。”
- “做一个角色灵感卡，能随机抽取我保存的角色资料。”

模型只返回类似以下概念信息：组件类型、标题、主题、数据来源、排序方式、按钮动作和布局尺寸。主程序校验后，调用内置的卡片、列表、计时器、图库、标签云、快捷动作等组件完成渲染。

### 第一批建议内置组件

1. 随机画廊 / 收藏轮播
2. 最近下载与最近浏览
3. 写作计时器和今日字数便笺
4. 标签云与元素统计
5. 本地模型状态与灵感台快捷入口
6. 个人玩法卡启动器

### 安全边界

- 只能使用软件公开的数据源与动作 ID。
- 默认禁止网络；需要联网的数据源以后单独申请权限。
- 不能读取原始文件路径、Pixiv Cookie、登录凭据或任意剪贴板历史。
- 限制组件数量、刷新频率、查询条数和图片解码数量。
- 保存前必须在隔离预览区展示；每次修改形成版本，可一键回退。
- 无法通过 Schema 校验时显示通俗错误，并保留用户原来的稳定版本。

## 5. 推荐实施顺序

### 阶段 W0：先把当前灵感台打磨稳定

- 消息发送立即回显，模型思考时不消失。
- 模型切换、停止、失败恢复、对话切换和参考图显示稳定。
- 不新增小组件运行时。

### 阶段 W1：个人玩法卡

- 增加自定义角色说明、玩法卡保存/编辑/删除。
- 提供 4～6 个官方示例，验证真实使用频率。
- 这是成本最低、最能释放模型能力的一步。

### 阶段 W2：小组件底座

- 建立严格的 Widget Manifest、Schema 校验、权限清单、预览和版本回退。
- 先由工程代码提供 5 个内置组件，不开放 AI 生成。

### 阶段 W3：AI 生成小组件配置

- 用户用自然语言描述需求。
- 模型生成 Manifest 草稿，主程序校验并渲染预览。
- 用户确认后才能加入纯净领域主页；模型不能直接写入生产布局。

### 阶段 W4：高级扩展（未来再评估）

- 如确实有开发者需求，再设计独立、签名、受权限控制的扩展 SDK。
- 任意 JavaScript/React 组件不得混入 W1～W3。

## 6. 第一轮验收标准

- 普通用户不看教程，也能保存一个自己的玩法卡并再次启动。
- 切换玩法卡不会污染其他对话或画评模型。
- AI 生成错误配置时，旧组件仍正常显示。
- 删除小组件不会删除画廊图片、对话或素材包。
- 关闭 AI 小组件功能后，纯净领域现有浏览、画廊和探索功能完全不受影响。

## 7. 当前决定

先完成 W0，再做 W1。暂不接 Anomalous，暂不允许 AI 写可执行前端代码，也不在当前灵感台一次塞入素材库、任务链和小组件三套复杂系统。
