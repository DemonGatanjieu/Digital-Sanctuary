# 个人标签偏好与 Prompt Bridge 实施规划

- 状态：P1 已完成；P2 待进入实施设计
- 立项日期：2026-08-24
- 当前阶段：P2 标签调音台准备
- 产品原则：越用越懂用户，但每次学习都可解释、可撤销、可重置

## 1. 为什么要做

当前探索保护只覆盖两类信号：

- 图片命中预设元素规则时隐藏；
- 用户点击“这张不该隐藏”时，系统放行具体作品并适度降低误伤。

它缺少反方向的表达：用户看见一张没有被规则命中的图片，却希望以后少看到包含相似元素的作品。

本任务补齐这一闭环，并把 WD Tagger 已经产生的标签向“提示词工作台”演进。过滤和提示词不是两套重复系统，而是共享一份经过用户校准的标签语义层。

## 2. 产品边界

### 2.1 本阶段要完成

1. 探索图片提供“少看类似”入口；
2. 展示经过筛选的候选元素标签，允许用户确认或取消；
3. 将确认结果记录为模型版本隔离的负向偏好；
4. 未来图片按标签置信度与个人偏好权重计算附加拦截分；
5. 告知用户本次学到了什么、数值如何变化，并允许立即撤销；
6. 与现有“这张不该隐藏”形成双向校准；
7. 设置页能够查看、启停、重置个人偏好。

### 2.2 本阶段不做

- 不根据一次点击直接拉黑图片中所有标签；
- 不学习 `1girl`、`solo`、发色等高频通用标签，除非用户显式钉选；
- 不把用户收藏、下载或画廊浏览暗中当作训练信号；
- 不让个人偏好改变本地画廊的可信显示；
- 不做图片局部区域遮罩。WD Tagger 只有整图标签，没有坐标；局部遮罩需要独立检测/分割模型；
- 不在 P1 直接连接 ComfyUI 或上传图片。

## 3. 用户交互

### 3.1 探索卡片入口

每张已经完成分析并正常放行的作品，在悬浮/聚焦时显示一个低干扰的“少看类似”控制。触发后弹出轻量标签选择层：

- **仅隐藏这张**：只记录作品例外，不学习标签；
- **少看类似**：使用系统推荐的区分性标签；
- **选择元素**：用户逐项勾选标签后确认。

第一版优先实现“少看类似 + 可编辑候选标签”，避免三个入口挤占 Pixiv 卡片。

### 3.2 候选标签

候选标签不是简单取置信度最高的标签。排序应同时考虑：

- 当前图片标签置信度；
- 标签是否属于可解释、可过滤的元素；
- 标签在普通图片中的常见程度；
- 用户历史负向反馈中的重复程度；
- 通用标签降权/排除清单。

选择层必须显示原始标签和置信度。用户没有确认前不得修改偏好。

### 3.3 反馈与撤销

确认后显示示例：

> 已隐藏本图；记录 blood 78%、guro 61%。blood 偏好权重 0.16 → 0.24。撤销

撤销必须同时恢复：

- 标签权重与证据次数；
- 当前作品的个人隐藏例外；
- 由本次学习产生的缓存失效。

## 4. 学习模型

### 4.1 数据单位

每次明确操作保存为一条不可变反馈事件：

```text
PreferenceFeedback
  id
  direction: dislike | false-positive
  normalizedUrl / artworkPageKey
  engine / engineVersion
  selectedTags: [{ label, confidence }]
  changes: [{ label, oldWeight, newWeight, oldEvidence, newEvidence }]
  createdAt
```

聚合画像按模型版本保存：

```text
TagPreference
  label
  weight: 0..1
  evidenceCount
  enabled
  explicit
  updatedAt
```

### 4.2 渐进更新

- 普通“少看类似”每次只小幅增加选中标签权重；
- 同一标签反复出现时，增长逐渐收敛；
- 一次反馈不足以形成强拦截；
- 用户显式选择标签仍立即形成最低有效权重，但不能突破安全上限；
- “这张不该隐藏”只回退与实际误伤原因相关的标签，不清空整个画像；
- 所有数值归一化并限制范围，防止数据损坏导致全页隐藏。

P1 使用确定性的有界权重算法，暂不引入不可解释的在线神经网络。

### 4.3 决策

预设硬规则与个人软偏好分开计算：

1. 命中用户明确启用的元素黑名单：按原规则隐藏；
2. 未命中硬规则时，计算个人偏好分；
3. 只有启用标签的组合分达到阈值且证据充足时，才隐藏并显示“个人偏好”原因；
4. 网络/模型失败仍返回 `unavailable`，不能冒充偏好命中；
5. 规则指纹必须包含个人画像摘要，使旧缓存自动失效。

## 5. 安全与性能

- 远程 Pixiv 页只能提交当前已分析图片的规范化 URL和用户选择的候选标签；主进程必须从已保存的分析结果重新验证标签与置信度；
- Renderer/Preload 不能直接提交任意权重；
- 画像与反馈历史只保存在本地 SQLite 偏好存储中；
- 历史设置容量上限，避免无限增长；
- 学习操作不重新运行模型，复用刚完成的 assessment；
- 画像变化只清理远程审查缓存，不触碰本地画廊分析任务或信任决策。

## 6. Prompt Bridge / ComfyUI 演进

P1 稳定后，将同一标签语义层扩展为“提示词调音台”：

1. 元素透视标签支持 喜欢 / 中立 / 避免 三态；
2. 导出原始 WD/Danbooru 标签、正向提示词和负向提示词；
3. 按生成模型保存转换配置，避免把标签串原样用于所有模型；
4. 支持将标签整理为本地数据集 sidecar；
5. 最后通过用户显式配置的本地 ComfyUI 工作流接口发送提示词/参考图；
6. 生成结果回到本地画廊时保存来源与工作流摘要，但仍视为用户主动导入的可信资产。

任何 ComfyUI 连接都必须是显式启用、仅限用户配置地址，并对工作流 JSON、文件路径和响应体做严格校验。

## 7. 分阶段交付

### P1：双向偏好学习（当前）

- 领域算法、协议与持久化；
- 探索卡片候选标签交互；
- 学习结果提示、撤销与设置管理；
- 单元测试、生产构建和真实 Pixiv 验收。

### P2：标签调音台

- 元素透视三态标签；
- 模型适配的提示词预览、复制和本地预设；
- 个人负向提示词库。

### P3：ComfyUI 本地桥接

- 连接测试、工作流模板和任务状态；
- 显式发送与结果回收；
- 来源、参数和工作流摘要持久化。

### P4：可选区域级遮罩研究

- 仅在目标检测/分割模型的准确率、显存和延迟预算通过独立评审后启动；
- 不与整图标签学习混成一个不可测试的推理管线。

## 8. P1 验收标准

1. 放行图片能够打开“少看类似”标签选择层；
2. 通用标签不会默认成为候选；
3. 主进程拒绝不存在于该图片 assessment 中的伪造标签；
4. 一次反馈不会导致大面积误伤，重复反馈会稳定增加对应权重；
5. 偏好命中时明确显示标签、图片置信度和个人权重；
6. 撤销后权重、证据与本图隐藏状态一致恢复；
7. 重启后画像仍存在，模型版本变化后不会错误复用；
8. 本地画廊任何入口都不受个人探索偏好影响；
9. 完整 `npm.cmd run verify` 通过。

## 9. 当前实现记录（2026-08-24）

已落地：

- “少看类似”候选标签与“仅隐藏这张”；
- 主进程基于已保存 assessment 的二次校验，最多展示 16 个候选、最多接收 5 个标签；
- 通用人物数量、构图和常见发色/瞳色标签不默认推荐；
- 模型版本隔离的个人标签画像、有界权重、重复证据门槛和组合分判定；
- 与“这张不该隐藏”共用的双向校准、数值提示和最近一次撤销；
- 设置页画像查看、单项启停与二次确认重置；
- 个人画像纳入远程规则指纹，本地画廊决策链保持不变。

自动验证已覆盖算法、类型、Vitest、Python unittest 与生产构建。正常重启后的真实 Pixiv 验收也已完成：

- 放行作品能够打开“少看类似”，候选标签来自本地 assessment；
- `1girl`、`solo`、发色等通用标签没有进入默认推荐，本次推荐 4 个具体元素；
- 一次反馈把对应权重从 `0%` 有界提升至 `18%`、证据从 `0` 提升至 `1`，图片显示“个人偏好”拦截原因；
- 测试反馈已精确撤销，标签画像、作品隐藏例外和反馈历史均恢复到测试前；
- 撤销不再清空全部持久化远程识别缓存，只清理当前进程的内存结果；旧结果依靠完整规则指纹安全复用。

P1 至此闭环。P2 开工前应先把“喜欢 / 中立 / 避免”三态、Prompt 预览的模型适配边界和复制/导出交互拆成独立可验收阶段。
