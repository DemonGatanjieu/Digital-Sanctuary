## 目标

把元素透视做成普通用户一眼能懂、长时间使用也不累的工具页。允许优化信息层级、留白、按钮文案、颜色、图标、响应式布局与微交互；不得改变已经落地的数据语义和后端边界。

重点优化：

- 三个页面的标题、说明和主要动作要一眼可辨；
- “正向 / 忽略 / 负向”比抽象的加减号更容易理解，并且都要有清楚的选中状态；
- 标签很多时保持稳定、易扫读，不出现套娃滚动和挤成细长竖栏；
- 高级设置、预设与本地 ComfyUI 发送保持次级层级，不抢走本图标签整理的注意力；
- 空状态、加载中、失败、后端未启用和任务进行中都要说人话，按钮要告诉用户下一步会发生什么；
- 兼顾主题、自定义字体、键盘焦点、`prefers-reduced-motion` 和 36～44 px 的舒适点击热区。

## 不可改变的产品语义

1. 百分比是 **WD Tagger 识别该元素存在的把握**，不是 ComfyUI 权重；不得自动输出 `(tag:1.15)` 一类伪权重。
2. 本图的“正向 / 忽略 / 负向”只在当前作品、当前页的工作过程中使用；切换作品、页或模型后重置，不积累成隐式用户画像。
3. 只有输出格式、个人负向词库和用户主动保存的预设可以通过 Prompt Bridge v2 持久化。
4. 浏览、收藏、下载、打开画廊都不能偷偷学习或改变提示词设置。
5. “设置探索拦截”只写入现有探索过滤后端；已经下载到本地画廊的图片永远保持清晰。
6. 只保留当前已经存在的本机 ComfyUI 显式发送链路。**本任务不得接入 Anomalous Model Browser，也不得放置尚未实现的一键发送按钮。**
7. Renderer 不得获得任意文件路径、任意网络地址或任意写盘能力；继续使用现有窄 IPC。

## 建议的精修方向

### 看懂画面

- 让“识别结果”和“识别把握说明”在首屏自然形成主次关系；
- 搜索、主要/高把握/全部切换与结果数量使用稳定对齐；
- 标签颜色可以表达把握区间，但不能暗示喜欢、危险或分级。

### 整理提示词

- 每行标签保留标签名、识别把握、三态选择；可采用分段按钮或清晰图标，但文字不能只剩 `+ / · / -`；
- 首屏显示本图选择摘要、重置默认和正负提示词预览；
- 输出格式、负向词库、预设和本地生成放入可展开的高级区域；
- 复制与发送必须有成功、失败、忙碌和不可用反馈。

### 设置探索拦截

- 明确这是“以后在探索里少看到类似元素”，不是给当前本地图打码；
- 选择标签、隐藏方式和触发把握形成顺畅的从上到下流程；
- 保存前显示将要生效的标签数和范围，保存后显示可理解的结果。

## 工程与验收要求

1. 任务开始前按规则记录 Git 基线；只提交与本任务有关的文件。
2. 先在真实 Electron 开发态打开一张已有 WD 标签的本地作品，不允许只看静态代码猜布局。
3. 至少检查正常桌面宽度和 `<= 760px` 窄宽度；检查标签很多、标签很少、加载、失败、ComfyUI 未启用五类状态。
4. 不引入新的重量级 UI 依赖，不把样式重新堆回 `styles.css`。
5. 不留下无动作按钮、假下拉框、占位入口或只在截图里好看的控件。
6. 补齐或更新相关测试，最后运行 `npm.cmd run verify`。
7. 在 `docs/reviews/element-inspector-polish/2026-08-24/` 保存一份执行记录，至少包含：改动摘要、桌面/窄宽截图名称、状态覆盖、测试结果、未解决问题。没有这份记录不得宣称完成。
8. 只有改变模块边界或持久化语义时才更新 `ARCHITECTURE.md`；本任务正常情况下不应改变它们。

## 完成标准

- 普通用户无需知道 Prompt Bridge、WD Tagger 或 IPC，也能理解三个页面各自做什么；
- 页面没有横向溢出、嵌套滚动、遮挡底部按钮或过窄内容列；
- 百分比说明不会被误解为生成权重；
- 三态选择不会跨作品暗中累积；
- 当前本地 ComfyUI 后端仍可显式发送，探索拦截仍可保存；
- 本地画廊不受探索隐藏规则影响；
- 自动测试、类型检查、构建和实机视觉检查均有可追溯记录。
