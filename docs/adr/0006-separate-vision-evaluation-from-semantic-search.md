# 0006. 视觉评估体系与多模态向量语义搜索的架构拆分决策

- **状态**: Accepted (已采纳)
- **日期**: 2026-08-15
- **决策者**: 核心架构团队

---

## 背景与问题陈述

在用户提出“为画作生成多维雷达图画像”与“支持外部 AI 分析与搜索图片”的需求时，系统面临两个不同的技术演进路径：
1. **视觉画像评测 (Visual Evaluation & Radar Profiling)**：对单张画作的技术特征（色彩/对比度/锐度）及美学意境（构图/光影/角色魅力）生成标量评分与文字解读；
2. **多模态语义搜索 (Multi-modal Semantic & Similarity Search)**：根据用户输入的自然语言描述或参考图片，在本地数万张画作中进行毫秒级以图搜图与意图检索。

如果将两套系统混合在同一个模块中，会导致 API 依赖耦合、存储膨胀以及无法独立离线运行。

---

## 决策

我们决定将 **视觉画像评测系统** 与 **多模态语义搜索系统** 严格解耦并分阶段实施：

1. **职责分离**：
   - **视觉评估体系 ([已归档实施计划](../plans/archive/2026-08-14-task-ai-radar-and-external-vision-implementation-plan.md))**：聚焦于可解释的维度评分（0~100）及文本解读，数据存储于 SQLite 结构化表 (`vision_evaluation_results`, `vision_dimension_scores`)，用于画作卡片、雷达多边形呈现以及基于固定维度的范围过滤。
   - **语义搜索体系 (`TASK_SEMANTIC_SEARCH_CLIP_AND_EXTERNAL_VISION.md`)**：聚焦于稠密特征向量（Dense Embeddings）的提取与余弦相似度检索，底库向量完全由本地轻量 CLIP/MobileCLIP 提取，绝不依赖昂贵且有隐私顾虑的外部大模型 API 进行全库预存。

2. **外部大模型的角色定界**：
   - 在视觉评估中，外部大模型充当“**主观评判者 (Critic)**”，仅在用户显式触发时按需调用单张图片；
   - 在语义搜索中，外部大模型充当“**查询意图理解与重排器 (Query Rewriter & Reranker)**”，不负责生成底层索引向量。

---

## 效果与优势

1. **隐私与离线优先**：全库语义搜索依然可以完全在本地单机离线运行，无需用户配置或消耗 API 费用。
2. **清晰的数据库模型**：避免在标量评分表中混合大型向量二进制 Blob，保证 SQLite 数据库的轻量与高效。
3. **渐进式演进**：雷达图画像可立即交付上线，向量搜索作为独立后续任务推进，降低系统复杂度。
